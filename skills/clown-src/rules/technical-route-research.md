# 技术路线研究与有界验证

用于真实入口上的机制假设、已知组件链和通用 0day 研究。先遵守 [研究边界](security-research-context.md)，漏洞类型与证明物按 [SRC 标准](../../../standards/src-acceptance.md)；本文件不扩大测试授权。

## 从正常操作到下一实验

先用 [知识索引的机制导航](../知识库/README.md#机制导航) 判断实际处理行为；[打穿短表](../知识库/打穿短表.md) 只补相似业务案例，详细方法在对应指南。九族是定位信任边界的地图，不是每站必测清单，也不是新增漏洞类型。

1. **正常操作与输入**：记录当前身份/租户、正常请求和预期结果，定位可控的 query/body/header/path、文件内容或存储字段。标出接收端、保存位置、后续消费者及其身份；看不到的步骤写未知。正常操作失败、身份过期或入口不可达时先修复基线/记 blocker，不把该拒绝当作下游机制阴性。
2. **当前阶段**：区分接收、存储、校验、解析/恢复、解释/执行、后续消费。某一步成功只证明到该步；保存成功不等于触发，状态码或错误栈不等于危害。
3. **竞争解释**：至少区分当前最相关的两种解释，例如「普通字符串/预期公式」与「进入额外解释上下文」、「格式校验失败」与「对象已恢复后才失败」、「任务排队」与「条件改变了查询耗时」。
4. **有界下一实验**：选择能最大限度区分这些解释的一处变化，写清前提、基线/对照、触发动作、观察位置与窗口、预期差异及反例。优先受控对象、最少结果、非破坏性标记；不要把换历史 payload 名称当实验设计。
5. **更新结论**：把请求/对象版本/任务 ID 与观察关联，说明支持哪个机制或危害、排除了什么、还有什么 blocker。缺消费者、配置、适用版本或观察设施时保留未知，不用扩大探针量补齐。

这些内容写入既有路线、事实和实验记录即可，不另建打卡表。源码辅助用于缩小输入到调用链、配置和版本的假设；源码可达、官方文档和本地复现都不能替代目标实际效果。

## 选择与研究

- 有具体中间证据、可控危险输入或明确组件利用链的真实入口优先；仅技术栈猜测低优先。普通越权/未授权线索主要作为技术链入口，不主动规划仅证明普通访问差异的验证意图；批量敏感数据、核心账户接管等真实高危害仍按既有证据线验证上报。
- 源码辅助：追踪输入、校验/转换、危险调用与可达条件，再用最小请求验证假设。黑盒：从真实请求/响应、语法差分和组件行为提出可证伪假设，不把指纹当利用成功。
- 通用 0day 不需要 CVE；已知组件路线须核实版本、配置、可达入口与链前置。按需读知识模块，已有可配置 web search 用于查官方公告、源码或补丁；不自动下载或执行不受信任 PoC。搜索关闭或不可用仍可推进通用机制路线，未知前提如实记录。
- 同一业务可串联多族：文件接收后被任务读取，再发生对象恢复或资源抓取。只有上一阶段证据支持下一消费者时才跨族续探；没有真实入口时先定位入口，不凭模块名称派验证。

## 执行与恢复

- route 记录入口、机制族、组件/参数、前置、假设、下一步、tested、remaining 与 outcome/reason。仅在有依据时尝试非破坏性编码、协议、参数位置、语法或利用链变体，逐项记录已测结果及剩余假设。
- 危险写入、数据修改、持久化与拒绝服务仍须审批，或使用保守替代证明；不得用下载来的 PoC 代替理解和验证。
- 同入口同机制族默认最多执行 6 次意图（续跑计数），上限不是目标。连续 3 个规划轮次无新增执行证据就换方向；新增变体名称、改写摘要、payload 或意图 ID 不算新信息。impact、路线级 negative、prerequisite_disproved、variants_exhausted、类型触顶或全局控制要求停止时不再续派。
- 单个变体没命中不等于路线级 negative；用 observed/evidence 支撑可靠结论，用 blocked 或 inferred 表达受阻/猜测。停止路线不能借“类型未覆盖”提权复活。
- planner 只读路线摘要；详情按节点 ID、分页事实、worker trace 与 OOB 查询拉取，不反复塞入全量历史请求或事件。

## OOB 最小闭环

仅在本轮工具列表实际提供 OOB 时使用：oob_generate 生成该意图专用 domain/http_url，放入获准测试请求后，用 oob_poll 按 probe_id 及其会话关联原请求、触发任务与窗口。分开记录「已分配」「已实际发送」「消费者已触发」「观察已完成」；只有分配地址不是一次实验。工具未提供或服务初始化失败就记录受阻，改用可用的本地证据或等待前置，不虚构回调。

- no_interaction：健康观察窗口暂无交互；service_unavailable：服务故障；observation_incomplete：窗口未完成。三者不证明目标无漏洞，不计进展，也不自动重跑整个 worker。
- 保留会话归属、有效期与实际观察覆盖时间。probe 过期、会话失效或任务在窗口之后才运行属于观察缺口；只有当前系统支持后续观察时才交接请求/对象/任务/probe 关联，否则记 blocker，不能用另一会话或另一次回连补证。
- 有回调仅证实相应交互，是中间证据；不能自动推断 RCE、完整 SSRF、可收 finding 或特定严重度。insufficient_impact 留作事实；继续取证必须满足信息增量、剩余预算与停止条件。
- DNS/HTTP 回连收集器不一定能提供指定正文、重定向、响应头或文件。当实验依赖这些能力时，先确认实际可控响应设施；缺少则记录设施 blocker，不能用一个回调域假装完成内容消费实验。具体见 [资源获取](../知识库/ssrf-test.md)。
- 不更改 report_finding 的类型锚定、复现、公开性与危害门槛。确认真实影响后按本类标准卡上报；否则保留事实和失败原因。
