# 对象恢复与反序列化

按 [技术路线研究](../rules/technical-route-research.md) 选择入口和停止条件；本篇不是历史 gadget 轮换清单。目标是定位不可信数据在哪一步变成类型、对象或有副作用的调用，再证明实际信任边界。组件名称、格式特征、报错或回连都不能独立证明 RCE。

## 入口与一次实验

正例：自己的导入文件、会话状态、消息或缓存字段可控，正常业务会把它恢复成对象；或 JSON/YAML/XML 中可控类型标记确实影响服务器选择的类型。反例：只有 Base64 Cookie、普通 JSON 数据绑定、仓库引用某库、客户端本地解码；这些没有证明服务端对象恢复。数据若先受签名、MAC、加密或白名单约束，先确认是否能合法生成自己的有效输入、哪些字段受保护以及校验顺序；校验前拒绝不能跳到下游 gadget。

用一个自己的正常对象建立基线：身份/租户 → 输入位置与编码 → 接收/保存 → 恢复动作 → 业务结果。输入可能来自 query/body/header、Cookie、上传文件，也可能是保存后被队列、定时任务或缓存重建读取的字段。记录对象版本、任务 ID、消费者身份和观察窗口；不能触发或看不到消费者就记 blocker。

例如“改一个类型字段后报错”有三种竞争解释：外层 schema 不接受字段、解析器识别了类型但拒绝加载、对象已恢复后业务校验失败。下一步应对照正常值与一个无害不存在的类型/受控字段，比较错误来源和业务结果，而非立即换执行链。只在范围和最小影响允许时使用这种差分；单个 500 仍可能来自统一异常页。

## 阶段、区分实验与反例

| 当前可确认阶段 | 最有区分力的下一实验 | 观察与反例 | 支持的结论/仍缺的前提 |
|---|---|---|---|
| 外层接收、解码或完整性检查 | 正常对象与仅改一处无害数据的对象成对；保持编码/压缩/签名条件可比 | 格式错误、MAC 失败、统一拒绝与后续业务结果分开；未通过外层检查不能解释为类型被过滤 | 只确认外层约束；缺有效载荷生成能力时停止此路径 |
| 格式解析 | 保留结构，仅换普通字段值或使用最小合法结构；必要时用单一受控格式错误区分解析器 | 语法错误只说明到了解析；普通字典/标量正常不说明可选择任意类 | 确认输入到解析器；查是否存在类型或恢复钩子 |
| 类型解析/类加载 | 对照已允许类型与无害不存在/不允许类型，保持业务字段一致 | “unknown type”“not allowed”、类名差分是类型解析线索；不能从类库指纹推断加载成功 | 需要实际类型配置、binder/filter、依赖与类加载边界 |
| 对象图/状态恢复 | 在受控对象上改变一个可回读的非敏感属性，与普通数据绑定结果对照 | 属性被保存不等于恢复时执行了钩子；对象恢复后仍可能被业务拒绝 | 确认状态进入对象；继续找真正被调用的方法或下游消费 |
| 恢复钩子或后续消费 | 已知调用前提下，用无害标记验证一个具体动作，并配无触发/普通字符串对照 | 单独 DNS/HTTP 可能来自 URL 校验、日志、预览器或另一任务；必须关联消费者与触发 | 只能报告实际观察的交互/访问/状态；执行与敏感读取另需实证 |
| 真实危害边界 | 用获准的受控对象证明越权读写、非预期资源访问或受限执行效果 | 自己对象正常恢复、产品有意提供的导入/脚本功能不自动越界 | 以已证危害映射当前可收类型；缺前提则事实或 blocker |

阶段不是所有实现都固定遵守的顺序：校验可能发生在恢复之前或之后，副作用也可能发生在最终业务拒绝之前。每个结论写清已观察到的最远阶段，避免把尾部错误当成全链未执行或执行成功。

## 三类恢复机制

### 原生对象流

Java `ObjectInputStream`、PHP `unserialize`、Python `pickle`、Ruby `Marshal`、.NET 格式化器等恢复的不只是普通字段；具体能否产生调用取决于实现、加载的类/函数、钩子、过滤和上下文。先从正常输入和调用证据识别格式，不用危险恢复 API “试着解码”未知文件。

| 格式线索 | 可保留的识别知识 | 不能据此推断 |
|---|---|---|
| Java 序列化 | 二进制头 `AC ED 00 05`，常见 Base64 前缀 `rO0AB`；可能有外层编码/压缩 | 所有 Java 请求都进入 `readObject`、目标含某条 gadget |
| PHP 序列化 | `a:`/`O:` 等类型标记、长度及属性编码；私有/受保护属性名可能含 NUL | `a:` 一定恢复对象，类可自动加载，任意魔术方法都会触发 |
| Python pickle | 二进制协议常见 `0x80` 加协议号；文本协议不必有此前缀；用 `pickletools` 等非执行分析看操作码 | `.pkl` 后缀、Base64 前缀或一次异常证明执行 |
| 其他原生格式 | 从正常样本、实际调用栈和依赖确定 Marshal/格式化器/自定义协议 | 仅凭 Web 框架或响应头选择运行时链 |

**Java：把“格式到达”与“链可用”拆开。** 核对流是否实际送入 `readObject`/`readUnshared`，恢复的是原生对象还是应用自己读取的基本值，及过滤器、类路径、类加载器、JDK/依赖版本。JDK 25 的文档说明序列化过滤可检查类、数组长度、引用数、深度和字节数；不能据此猜目标已启用什么过滤器。`InvalidClassException`、`ClassNotFoundException` 和过滤拒绝只能按其所在阶段解读。

历史 URLDNS 的价值是研究恢复过程中的名称解析，不是“所有 JDK 通用 RCE 探针”；DNS 也可来自非恢复路径。CommonsCollections、CommonsBeanutils、Spring、Groovy、Rome 等是**依赖与调用路径候选**：须先有精确版本/类存在、可构造对象图、触发方法、过滤及运行时限制的证据，再选一个与当前假设匹配的非破坏性验证。没有这些前提不运行整套 ysoserial 矩阵，不自动下载或执行外部 PoC。PriorityQueue/比较器、哈希/相等比较等只在该容器恢复或消费者实际调用它们时才有意义。

Shiro rememberMe 需要确认处理流程、实际密钥/算法/完整性与类路径；Cookie 被删除只是拒绝线索，不是“默认密钥有效”。RMI/JMX/Hessian/Kryo 等先确认暴露的方法、认证、输入到恢复器及注册/白名单规则；“服务存在”“未强制注册”不等于可达执行。反序列化触发 JNDI 或外连也不能跳过当前运行时、协议、远程加载和出网限制，直接套用旧版远程代码加载结论。

**PHP：恢复与消费钩子分开。** `unserialize` 恢复对象后会按实现调用已定义的 `__unserialize()` 或 `__wakeup()`；`__destruct()` 取决于对象生命周期，`__toString()` 需要字符串转换消费者，不是四个方法按顺序自动执行。核对允许类、自动加载和实际魔术方法；`allowed_classes` 限制也不等于整条业务链已安全。POP 链要把可控属性逐段连到真实调用，不能只列类名。

Phar 必须同时追踪上传/存储路径、是否被识别为归档以及后续消费者。**PHP 8.0 起 Phar 元数据不再自动反序列化**；不能把所有 `file_exists`/图片读取/`phar://` 访问当成对象恢复。明确 `Phar::getMetadata()` 等实际读取元数据的行为和其反序列化选项，再判断是否进入对象恢复；版本或消费者未知时回到 [文件生命周期](file-upload-test.md)，不盲试历史 Phar 链。

**Python：协议描述与恢复动作分开。** `__reduce__` 在序列化时描述重建所用可调用对象、参数和状态；恢复时可能调用这些对象或 `__setstate__`，还要看 `find_class`、`persistent_load` 等自定义行为。不能笼统说 `loads` 会调用输入对象的 `__reduce__`。对缓存、模型、任务消息等先确认实际 `load/loads` 消费者与完整性；不要用 `pickle.loads` 检查未知样本。受限 unpickler 的存在既不证明可绕过，也不代表所有后续消费者无风险。

Ruby Marshal 的 `_load`/`marshal_load` 与对象后续方法需要对应类和实际恢复调用；PHP/Python/Ruby 的语言判断都不应变成跨语言 payload 轮询。

### 多态数据绑定

JSON/YAML/XML 可能只是普通数据，也可能允许输入影响类型。区分显式类型标记、目标字段的声明类型、全局/局部设置、白名单/binder、构造器与 converter；先证明可控标记改变了类型解析，再研究对象行为。

- **JSON.NET**：官网当前设置文档中 `TypeNameHandling` 默认是 `None`。非 `None` 的相关设置可能读取 `$type`，但作用范围、属性设置、`ISerializationBinder`、元数据位置与自定义 converter 都会改变行为；通常元数据应在对象开头，`ReadAhead` 可改变这一点。`TypeNameHandling != None` 不是 RCE 结论。先用无害类型/普通字段差分确认当前调用实际接受类型，再核对允许类型的行为；不要直接轮换 ObjectDataProvider 等历史链。
- **Jackson/Fastjson/XStream**：核对调用方式、声明类型、多态/类型标签是否开启、允许类型与精确版本；“依赖里有库”“报了 autoType 错误”“XML 含类名”分别只是线索或拒绝。模板中的类型名称不能替代实际实例化证据；缺版本/配置就保留适用性未知，不背一张跨版本绕过表。
- **SnakeYAML/其他 YAML**：普通映射与可构造自定义类的标签不同。当前 SnakeYAML `LoaderOptions` 主分支源码使用 `UnTrustedTagInspector`；不能把 `load` 一律视为任意类恢复，也不能将主分支状态外推到目标发布版本。确认实际构造器、标签检查器、允许类型和消费者后再设计对照。

### 自定义恢复、签名状态与延迟消费

`from_dict`、对象工厂、动态导入、属性写入、模板/规则恢复等即使不用“反序列化库”，也可能让数据选择类型或行为。沿“输入字段 → 分派/赋值 → 后续方法”找边界；普通键值写入不是代码执行。若原型/属性污染影响后续模板或配置，需另证属性确实被该消费者读取，见 [原型污染](prototype-pollution-test.md) 和 [解释执行](el-injection-test.md)。

.NET ViewState、会话包和其他签名状态先核对有效 MAC/签名、页面/用户绑定、加密与格式化器路径。只能解码自己的状态、收到固定错误、发现历史 machineKey 示例都不证明可伪造；缺合法修改通路时不能直接生成历史执行链。格式化器在目标运行时是否启用/可达需独立确认。

延迟任务的最小链：保存自己的受控样本并读回原始值 → 明确提交/恢复/导入动作 → 在自己的任务或产物上观察无害标记 → 无触发与普通字符串对照。保存响应、队列接受、任务报错、对象恢复、后续执行分别记录，尤其不要用上一任务或另一会话的回连补证本次样本。

## 收束与证据

- 源码、官方文档和依赖清单用于缩小假设；记录版本、配置、输入到调用及仍未验证的消费者，不能替代目标实证。
- 无回连要区分未发送、消费者未运行、DNS/HTTP 不通、工具不可用、窗口未结束以及真正的机制反例；按公共路线规则处理 OOB 状态。格式/类型拒绝只收束当前路径，不证明应用不存在别的恢复路径。
- 同一入口不因更换链名称重置预算。适用版本、类/配置、完整性条件或消费者缺证据时记具体 blocker；只有证据否定所需前提才是 `prerequisite_disproved`，不能混同未知与已证伪，也不继续穷举。
- 最终仅陈述已证实的阶段和危害；普通对象恢复、解析错误、组件名称或 OOB 单独交互留作事实，不自动升格漏洞类型/等级。

## 来源与适用性

以下为 2026-11-25 核对的一手文档/源码，**未对目标或代表性本地应用实测**；不表示目标采用相同版本与配置。其余历史链仅作待核对假设，不宣称版本兼容。

- [Java 25 ObjectInputStream](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/io/ObjectInputStream.html)：原生对象流、可选过滤及恢复语义；只代表该版 API 文档。
- [PHP unserialize](https://www.php.net/manual/en/function.unserialize.php)、[PHP 8.0 不兼容变更](https://www.php.net/manual/en/migration80.incompatible.php)、[Phar::getMetadata](https://www.php.net/manual/en/phar.getmetadata.php)：恢复钩子、PHP 8.0 Phar 变化及显式元数据恢复。
- [Python pickle](https://docs.python.org/3/library/pickle.html)：官网当前 Python 3 文档，reduce/重建、类解析和非可信输入边界；具体协议与自定义 unpickler 仍需现场核对。
- [JSON.NET Serialization Settings](https://www.newtonsoft.com/json/help/html/SerializationSettings.htm)：官网当前设置文档，未标注目标发布版本；默认值、类型处理与 binder 不是利用兼容表。
- [SnakeYAML LoaderOptions 源码](https://github.com/snakeyaml/snakeyaml/blob/master/src/main/java/org/yaml/snakeyaml/LoaderOptions.java)：核对当日可变主分支的标签检查默认实现，不作为目标版本结论。
