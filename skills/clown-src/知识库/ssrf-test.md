# 资源获取与 SSRF：请求能力到后续消费

路线、OOB 和停止规则见 [技术路线研究](../rules/technical-route-research.md)。URL 字段不是漏洞；要区分谁请求、请求能做什么、结果被谁消费以及跨了哪条边界。与文件导入/转换串联时读 [文件生命周期](file-upload-test.md)。

## 从正常业务定位请求

正例：图片/文件导入、预览、Webhook、远程配置、PDF/截图、对象回源或构建依赖会由服务端获取指定资源；自己能合法配置输入并触发消费者。反例：URL 只被保存/回显、浏览器直接加载、只做 DNS 校验，或只有参数叫 `proxy/url`。正常向用户指定公网地址发 Webhook 本身不等于越界。

记录当前身份/租户、输入位置、自己的对象版本、同步/异步触发动作、任务 ID、消费者与观察窗口。候选链为“接收 URL → 解析/校验 → 解析地址/连接 → 重定向 → 读取响应 → 存储/解析/转换/执行”；没有证据的环节标未知。一次回连不能跳过其间所有阶段。

**一次推理示例**：导入任务保存 URL 后返回 200，但预览为空。竞争解释是只保存尚未运行、工作器请求失败、抓到了内容但解析失败。用一个能提供固定小文件和唯一标记的受控端点，分别观察请求日志、任务状态与产物；再用未触发对象对照。DNS 收集器只能回答部分连通性问题，不能代替这个文件响应。

## 先刻画请求能力

只确认当前假设需要的能力，不为填表把每项都测一遍。优先自己可控的正常资源与少量单变量对照。

| 能力/阶段 | 最有区分力的有界实验 | 观察与反例 |
|---|---|---|
| 请求发起者与协议 | 用唯一 URL 触发一次正常功能，关联受控端日志、任务和原始响应 | 浏览器访问、预校验 DNS、重试/其他任务都可能造成命中；仅 User-Agent/IP 不足以唯一归属 |
| 方法、路径、查询、头、正文 | 在受控接收端记录实际请求；仅改变业务允许的一个输入 | POST/GET、固定头、认证头、正文是否可控分别确认；“可填 URL”不等于可构造任意请求 |
| URL 解析/地址校验 | 正常目标与一个针对已知校验差异的等价表示成对，比较各层实际目标 | 一次 403/400 只说明当前表示被拒；不据此喷 IP 编码、协议、网段或端口 |
| 逐跳重定向 | 两个受控端点：第一跳返回一个明确 Location，第二跳记实际方法/头/目标；与无跳转资源对照 | 请求首跳不证明跟随；错误码不证明到了第二跳；不同客户端会拒跳、改方法或移除敏感头 |
| 响应能力 | 提供小的固定正文、明确 Content-Type/状态或单次重定向，看回显/存储/产物如何变化 | 能收回调不等于能指定响应；只见 HTTP 请求不说明服务器读完或解析了正文 |
| 延迟/二次消费者 | 保存自己的 URL → 明确触发任务 → 关联抓取与产物；需要时用下一次受控读取区分缓存/复用 | 保存 200、队列接受、旧产物、无触发对象均不能作本次成功证据 |
| 边界与危害 | 在范围允许且能力前提已满足时，验证一个具体受控目标/对象的访问或操作边界 | 公网回连、已公开内容、正常 Webhook 不等于内网响应、敏感读取或执行 |

## OOB 与内容响应设施

- 本轮实际提供 OOB 工具时，`oob_generate` 分配本意图地址，再实际发送获准请求，触发消费者，最后 `oob_poll` 以 probe_id/会话/时间窗关联。分配成功、请求已发送、消费者已运行、观察完成是不同状态。
- `no_interaction` 只说明当前窗口未观察到交互；`service_unavailable` 是设施问题；`observation_incomplete` 不可当阴性。即使健康检查通过，目标出网/延迟任务仍可能受阻；若工具有健康状态，保留本轮状态与时间。
- DNS 命中通常最多支持名称解析相关交互；HTTP 命中可支持相应请求。不能从外网回连推断内网地址已被访问，也不能从无回连排除有回显或被拦出网的路径。
- 实验若需要重定向、特定响应头/正文、归档或图片内容，必须有**已获准且实际可控响应的设施**，并确认功能。只有回连收集器、工具未提供或不能返回所需内容时，明确写设施 blocker；不虚构服务器、不能用无关公网服务冒充受控对照。

## 重定向、规范化与协议边界

首先区分输入校验的是原始字符串、规范化后的 URL、解析出的地址还是每次连接/每一跳；只有具体层间差异支持时才研究一种变体。不要默认十进制/八进制/IPv6、用户名段、DNS 变化等在当前解析器同义或有效。

HTTP 标准允许历史上 301/302 场景把 POST 改为 GET，303 表达另取资源，307/308 保留方法；**实际客户端是否跟随、如何转发头/正文以及是否重新校验地址都需受控逐跳观察**。固定 POST 入口收到 405 不是漏洞也不是整条路线阴性；先证明当前客户端的重定向能力，不能直接将 302 指向元数据当作已知 GET 通路。

非 HTTP 协议先确认客户端支持、应用允许、实际请求字节与下游服务行为；`file://` 可转到文件读取，其他协议也不等于自动任意 TCP/命令。无证据不轮换协议或构造服务命令；不以清库、写计划任务等破坏动作作能力验证。

## 深入案例

### 云厂商元数据路径差 / 匿名网关

保留的机制是**回环与链路本地/元数据地址过滤不一致、厂商路径不同、匿名身份与代理能力边界不一致**，不是固定地址命中即接管。

1. 先确认网关是否真的代请求、当前身份可调用何种功能，以及方法、头、跳转和回显能力。匿名 token 也有其授权范围，不能一概当无限权限或无风险。
2. 元数据候选需有当前云环境/消费者证据和范围许可，再查该厂商当前文档的地址、路径、会话 token/请求头等前提。仅能 GET URL 不保证满足其要求；某厂商路径 404 不说明其他路径成立，也不支持盲轮询所有云厂商。
3. 已观察的目录、实例标识、凭证正文、凭证实际能力是不同证据层。只看到目录/实例信息不能声称拿到凭证；窄角色不能声称接管账号。按既有标准决定是否已足够，不把取得或使用云凭证设为所有 SSRF 的必经步骤。
4. 若任务确实获准验证已取得凭证，仅做与待证危害直接相关的最小操作；某 API 拒绝先解释权限边界，不因拒绝无限切换云服务。敏感值只按会话/报告规则处理，不写知识库。

### 公开 GOPROXY

`/go/`、模块 `/@v/list` 或“代理”名称不证明服务会直接执行 VCS 获取。区分只读缓存、转发上游代理、直接获取模块和后台构建任务；用正常模块请求及自己的受控模块路径观察实际链。

只有确实发生模块发现时，才考虑 `?go-get=1`/`go-import` 这一分支；需要能提供该元数据正文的受控站点。继续前核对实际工具版本、代理/回退、VCS 许可和协议配置，观察发现请求之后是否真的访问仓库。旧案例的 hg 分支不是 git 超时后的默认替代：缺 VCS 消费者、配置不允许或只有上游缓存时即收束/阻塞。

发现请求、仓库获取、命令工具报错、响应内容进入产物分开记录。只收到域名回连或看到 hg/git 字样不等于内部访问；仍需具体目标响应和危害证据，不轮换历史仓库执行链。

### 对象存储回源与读取时序

前提是自己能配置回源目标、控制同一测试 key，并且业务存在“检查对象 → 稍后再次读取/导入”的分离消费者。先用两个稳定版本的无害内容、唯一标记和请求日志确认缓存/回源/后续读取；没有回源或第二消费者时不做竞态。

确需区分检查时与消费时内容，才按 [竞态指南](race-condition-test.md) 在自己的可清理 key 上做有限次切换；记录检查版本、消费版本、回源日志与产物。回源能配置、请求受控外站、状态码变化都不等于内网访问；重定向是否跟随按前节逐跳确认。若文件被解析/转换，沿 [文件生命周期](file-upload-test.md) 追踪其真正消费者。

## 来源与适用性

本文机制实验不预设云产品版本；现场的客户端、网络、授权与消费者仍需证据。以下一手参考于 2026-11-25 核对，**未对目标或代表性本地应用实测**：

- [RFC 9110 §15.4 重定向](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.4)：HTTP 状态码语义，不保证具体客户端行为。
- [Go Modules Reference：模块获取](https://go.dev/ref/mod#module-fetch)：官网当前 Go 工具文档；代理协议、直接获取、发现与 VCS 限制需按实际工具/配置判断，不外推所有第三方 GOPROXY。
