# 文件生命周期：接收、存储、校验与后续消费

路线选择、组件/通用机制研究、OOB 与有界停止见 [技术路线研究](../rules/technical-route-research.md)。

## 从自己的正常文件定位阶段

正例：头像、附件、归档、导入或富文本的可控字节/文件名会影响存储、解包、转换或后续任务，能触发和观察自己的对象。反例：只拿到上传 URL、静态 CDN 原样下载、自己的 key 可覆盖，均不证明跨用户写入或执行。先确认正常上传身份/租户、字段与文件内容、对象 ID/key/版本、重命名、后端/对象存储、读回方式及后续任务；没有消费者证据不轮换扩展名或旧转换器漏洞。

| 当前阶段 | 最有区分力的下一实验 | 观察/反例与结论边界 |
|---|---|---|
| 接收 | 正常小文件与只改变一个无害属性的文件成对，固定身份和上传字段 | 收到 200、预签名或任务 ID 只说明接收/排队；实际字节可能未落库 |
| 存储 | 用唯一标记确认自己的对象实际内容、名称、权限、版本和读回来源；对照不存在 key | 重命名/CDN 缓存、只返回 URL、只能覆写自己对象不证明任意文件写 |
| 校验 | 在已知格式的最小文件上单独改变声明类型、名称或内容，观察哪个环节拒绝/转换 | 后缀/Content-Type 放行不等于执行；预校验成功后仍可能重新校验 |
| 解包/展开 | 用少量无害条目确认落地路径、条目类型、重名处理与输出清单 | 仅上传归档、归档被拒/原样保存、文件名在列表中出现，不证明已经写到该位置 |
| 解析/转换 | 正常最小样本与一处结构变化对照，观察本次预览/缩略图/导入输出 | 解析错误、进程异常、耗时或库名仅说明阶段/候选，不证明读写或执行 |
| 后续消费 | 明确触发自己的预览、导出、构建、恢复或定时任务，关联输入版本、任务与产物 | 保存成功、排队、下载原文、旧缓存产物不等于消费者处理了本版本 |
| 危害 | 按已证实边界在受控对象上取最小证据，区分跨对象读写、资源获取、解释执行 | 文件可访问/可覆盖、脚本内容反射、服务端解析与服务端执行是不同结论 |

实际顺序可能是“先存储再校验”或“临时区解析后持久化”；不要把表当固定管线。一次实验只回答当前最关键的问题，例如“转换器读的是刚上传版本还是旧缓存”，不把完整生命周期变成每文件必测清单。依赖精确字节/归档条目时保留输入摘要和读回对照；上传助手的编码、换行、文件名或正文转换必须显式记录，不能把变形后的样本当原实验。

## 解包、规范化与链接

竞争解释包括上传器已重命名/剥离路径、解包器保留条目名、检查器与写入器采用不同规范化、或只生成清单尚未写盘。先用正常归档与唯一标记确认实际解包位置；需要验证路径边界时，仅在已获准的受控目录/对象上构造最少条目，不使用海量/深层压缩制造资源消耗。

- **路径条目**：围绕已观察到的规则，选择一种 `..`、绝对路径、分隔符/编码差异或重名条目对照，记录规范化后实际落点。仅清单显示特殊名称、路径被剥离或输出被固定在根内是反例；没有落地读回证据不声称穿越成功。
- **链接与间接引用**：先确认该归档/平台/提取器是否保留链接条目、后续写入或读取是否跟随链接；被拒、转普通文件、根内解析与越界跟随是不同结果。用自己的标记目标及无链接对照；不能从“支持归档”推定符号链接/硬链接可用。
- **检查与写入分离**：若预检查和真正展开采用不同库/时机，比较它们看到的条目名、版本与结果；重复文件名/路径别名是否覆盖需实证。单次预检查放行或报错不代替最终写入观察。路径细节见 [路径与包含](path-traversal-lfi-test.md)。

## 解析、转换与临时文件

图片/PDF/Office/压缩包/配置导入可能调用库或外部工具，但“文件类型 + 依赖名称”不够选择历史链。核对实际消费者、版本、启用的格式/功能、配置、传参位置与运行身份；源码中的调用只帮助缩小假设。

选择最小无害文件，单独改变一个与当前假设有关的结构/字段，与正常输出比较：原样保存、读到了外部资源、读取受控本地标记、产生新文件、进入表达式解释或真正执行是不同阶段。依赖远程内容时需要可提供指定正文/响应的设施，按 [资源获取](ssrf-test.md) 处理；仅 DNS 回连不证明转换结果含该内容。

临时路径、文件重命名和清理竞态只有在“校验时对象”和“消费时对象”可区分时继续：记录对象版本/摘要、临时/持久位置、任务和观察窗口；先用稳定的 A/B 无害版本证明存在两次读取，再考虑范围允许的有限时序实验。没有第二消费者、版本不可关联、临时文件不可观察，记 blocker，不靠高速替换碰运气。

## 保存 → 触发 → 观察的文件链

例如导入归档“上传成功但未生成记录”：可能尚未解包、格式校验失败、转换后导入失败，或观察的是旧任务。保存自己的小归档并读回/确认版本 → 显式触发导入 → 记录任务完成/失败阶段 → 对照产物中的唯一标记和无触发对象。只看到队列接受就结束在该阶段；没有获准触发或产物读取能力是 blocker。

文件作为模板/脚本在预览、构建或调度时解释，需证明具体消费者及执行身份，再转 [解释执行](el-injection-test.md)；作为对象流恢复转 [对象恢复](deserialization-test.md)。Phar、模板、模型文件或解析器历史链都需版本/配置/消费者证据，不因扩展名自动尝试。

**写入不等于执行**：自己的文件可被 HTTP 下载可能只是 CDN/静态存储；同源浏览器执行属于客户端上下文；服务端读取/解析也未必调用指令。只有相应消费者实际产生受控的无破坏性执行效果，才支持执行结论。受控跨身份写入与写后消费分别证明，避免把“同前缀能盖自己的 key”外推成覆盖官方对象。

## 存储与下载案例（有对应前提再读）

### STS / 对象 key 通配覆盖（短表有指针）

认：正常上传先申请 STS/预签名，且有证据表明可控 `filename` / `Action` / key 前缀参与签发策略。对象 key 的 md5 形状、桶名或前端 AES 只提供定位线索；字段名不一致可以继续追踪实际策略输入，不凭这些指纹派通配探针。

打：

1. 保留自己的正常前缀作基线。若输入直接拼进资源策略，选择一个有区分力的边界变化，例如通配符或空前缀；比较实际签出的 Resource/Action，不把“长度未校验”当成策略已扩大。
2. 旧案例里不同数量的 `*` 曾命中不同桶/前缀，这只是特定策略拼接现象。先确认当前策略语义与归属，废桶、自己的前缀和跨归属范围分开记录，不依次轮换数量。
3. 路径参数参与策略且有规范化差异证据时，用一对受控路径判断校验与签发是否解释一致；只比较签出的范围还不能证明实际读写权限。
4. 用正常业务获取获准第二身份对象的准确 key，保留所有者与拒绝基线；md5 形式本身不说明对象公开或可跨归属访问。
5. 用获准的受控第二身份对象验证凭证是否跨归属读写；只改自己的对象不能证明覆盖他人对象，写入须可恢复
6. assumerole 的 `filename=*-*`（或 `*`）、`Action=*` 仅在字段确实参与 Policy 时作候选，核对签发策略与实际权限差分。List/Delete 403 分别只说明该操作被拒，若有独立依据再对受控 key 验证 GET/PUT，不遍历删/盖真实对象。匿名票在另一个网关被拒不代表本口行为；仍按当前会话与授权边界判断。query `upload_dir`/`dir` 原样进 Policy 时可围绕前缀边界设计对照。CDN 读回要排除旧缓存
7. 只有当前存储 API 和凭证允许相关操作时，才在获准可恢复对象上验证 ACL/授权变更；具体字段与语义按该厂商当前文档核对，不把 COS/OSS/S3 的头互相照搬。必须观察实际权限变化，只 200 不算接管。
8. token 口若前端写死签名材料，先区分“能生成有效签名”与“策略越界”。用获准 key 验证其实际读取边界；拿到 appId/bucket 或拼出 CDN 地址不等于读到私有对象，不枚举真实证件文件补证。
9. **落地页写死 supabase / nocode `role=anon` JWT 时，数据表与存储需各看实际策略。** 沿正常上传请求在获准前缀创建自己的探测文件，再用同一路径和更新方式改成第二串标记，读回并清理。旧案例的 `x-upsert: true` 只是候选接口线索，按当前版本/实际请求核对；同前缀能盖自己刚传的**不证明**能盖官方或其他归属对象。需策略与获准的受控跨归属对照才能继续；不要真盖官方运营图。

   适用性核对：2026-11-25 阅读 [Supabase Storage Access Control](https://supabase.com/docs/guides/storage/security/access-control)，当前文档区分 `storage.objects` 的 INSERT 与覆盖所需的 SELECT/UPDATE，并示例按 `owner_id` 限制；这支持按操作/对象检查策略，不代表目标配置。未对目标或代表性本地应用实测，不能外推其他 nocode 产品。

算成：在当前授权范围内，受控第二主体本应拒绝的对象被读/改，原读取链路确认内容变化且已恢复；或其他符合收取标准的实际越界。只列出 key、自己对象可 upsert、签出宽策略但实际操作被拒，不等于覆盖他人文件。

假点：`*` 只签发废桶；通配了但覆盖 403；改的是自己的对象；策略服务端写死盖不掉；只通自己前缀；CDN 一直不刷新看起来没盖上。单站没中不删短表这行。

和 S3 预签名「改自己的 Content-Type」、和「带签 URL 改租户读他文件」、和下面「桶策略对匿名全开」「签名没绑 Host」「签名覆盖 Content-Type」都不是一条：本条研究 **可控策略输入是否扩大凭证范围并造成已证越界**。

### 签名没绑 Host（短表有指针）

认：COS / OSS / S3 带签 URL；query 里 `q-header-list`、`SignedHeaders`、`X-Amz-SignedHeaders` **没有 host**。有对象存储带签才打，没有不要空换域名。

打：

1. 看签名参数里签了哪些头。没有 `host` 再往下。  
2. 把 URL 的主机换成**同账号另一个桶**的域名（证书 SAN、报错、控制台、JS 里抄），path 和签名 query 先不动。  
3. 再加 `?uploads`（或已有 query 后 `&uploads`）打 ListMultipartUploads；能 GET 对象也打。

算成：列出或读到**别的桶**里的对象。只换域还是自己这个桶 → 没成。

假点：签名罩住 Host；换域 403；只有自己这个桶。单站没中不删短表这行。

和 STS `*`（钥匙范围被通配）、和带签 URL 只改租户字段 **不是一条**：本条是 **Host 没进签名，同一把签能打到别的桶**。

### 签名覆盖 Content-Type（短表有指针）

认：对象内容你能控（自己传的或 STS 能盖的）；对象上的 Content-Type 被卡死（image/jpeg 一类）；手里有临时钥或能再出预签名。

打：

1. 上传时改 CT 那一枪还打（`text/HtMl`、`text/html,image/png`）。那是「签的时候没把 CT 签进去」。  
2. **事后再签**：用临时钥给**已有对象**出一枪带 `response-content-type=text/html`（COS/OSS 支持签名覆盖响应头）的 GET。  
3. 用这把新签 URL 在浏览器打开，不要只看 curl 的 Content-Type。

算成：浏览器当 HTML 执行（存储 XSS）。下载仍是附件/原 CT → 没成。

假点：签名接口拒这个参；只能改自己不可达的对象；`X-Content-Type-Options: nosniff` 且 CT 仍是图。单站没中不删短表这行。没对象存储、没临时钥不要空签。

和「上传 PUT 时改 Content-Type」不是一条：那条改的是**写入时**的类型；本条是 **读的时候用签名把响应头盖成 HTML**。

### webpack 明文对象存储永久钥（短表有指针）

认：管理台 / 运营后台 webpack 把生产 `accessKeyId`+`secretAccessKey`（MSS / S3 一类永久钥）打进 JS。或 Weblogic `/console/login/LoginForm.jsp` 内联 `_reportCfg` 一类的 `SRV_` 钥。上传签 `getUploadSign` 是前端 HMAC-SHA1 算 policy，不是走登录后的 STS 口。policy 里 `starts-with $key` 经常是空串。

打（不登录）：

1. 抄 online/prod 的 AK/SK（实值只进报告）  
2. 自己算 POST policy，expiration 拉长，`starts-with $key` 按 JS 原样（空就空）  
3. POST 桶：对照假签 `SignatureDoesNotMatch`、无签 `conditions has no signature`  
4. 在获准测试前缀 PUT 后 CDN GET；只清理自己的探测文件。要证明跨归属覆盖，用可恢复的受控第二身份对象，不改官方运营内容
5. List/PUT 403 别停：先 `GetBucketLocation`。对照假 AK `InvalidAccessKeyId`。页面桶名拼错（staic/static）试邻近  

证据分层：真签成功可支持凭证有效，实际范围由操作和对象归属决定；桶地域、自己的 PUT、跨归属覆盖不可混为一谈。是否可收按当前标准和已证危害判断，不为了补等级覆盖官方对象。

假点：InvalidAccessKeyId；只能传到固定前缀；getUploadSign 其实是 SSO 接口没有本地钥；钥过期。密钥实值不进库。单站没中不删短表这行。

和 STS 通配（先申请临时票）、和桶策略对匿名全开（不用钥）、和 viewer XOR 藏 COS 永久钥（要解开再问 AccountId）都不是一条：本条是 **webpack 明文永久钥 + 前端自己算签**。

### 桶策略对匿名全开（短表有指针）

认：官网/控制台的图、使用指南、协议直接挂在 OSS / cloudrun 一类桶域名上；桶根或 `?policy` / GetBucketPolicy / 等价策略接口能拉开，语句是全 Allow。

打：

1. 策略能看就看；再对桶做 LIST（无 AK）  
2. 用明确获准、可恢复的受控对象验证匿名写边界，不改桶策略或真实运营文件
3. 由对象所有者与匿名身份建立前后对照，从原读取链路确认版本变化，再恢复/清理

算成：匿名身份改变了本应受保护的受控对象，且原读取链路看到该变化。只证明匿名能 LIST 或能向自己的新 key 上传，不证明覆盖既有对象；公开文件原本可读也不是越界。

假点：策略只读不能写；PUT 只能落自己前缀；下到的本来就是公开静态页。单站没中不删短表这行。

和 STS `*`（要先申请凭证、key 打成通配）、和 filename `../` 穿越租户目录、和 Azure 容器级 SAS 都不是一条：本条是 **桶策略对匿名放开，不用凭证**。

### 存储代理 sign key=/（短表有指针）

认：业务网关把对象存储代理成 `/api/storage/sign`（或同类 sign），query 只吃 `key`。`key=/` 或 `key=.` 回 S3 `ListBucketResult` XML，不是申请 STS。

打（不登录）：

1. GET `?key=/`（再试 `.`）。对照乱填 key 应 `NoSuchKey` / 400  
2. 列表里抄业务前缀（`images/` `editor-` 一类）再 GET 同一口  
3. 看对象是不是未公开素材，不要停在官网 Banner  

算成：列出并读到他人未公开对象原文。

假点：只有 app-static 公开静态；`filename=` 400 当没口。单站没中不删短表这行。和 STS 通配（先领钥）、桶策略匿名全开（直打桶域）不是一条：本条是 **业务网关自己当 List/Get 代理**。


### 制品下载详情把 uin 有无当登录闸（短表有指针）

认：软件/专有云/物料下载中心；详情 JSON 有 `DownloadURL`；前端从 Cookie 抄 `uin`/`skey` 拼 query。空身份时 URL 是空串、页面跳登录。

打：不登录 GET 详情，身份字段填非空假值（`uin=1`），不要 skey。对照空 uin。拿回的带签 URL Range GET 前几十字节看 ELF/PK。

算成：专有云安装包/内部部署文档真文件。空 uin 也出 URL → 完全无鉴权（另一条）。带签 403 / 只有公开说明书 → 没成。

### 入驻 JS 写死 fileKey（短表有指针）

认：入驻/资质 SPA 打包 JS 的 mock 或演示 formData 写死一长串密文 `fileKey`。站点根 301 到新域，**旧 host 下载口可能还活**。不要把 mock 当占位丢掉，也不要把 301 当整站废。

打（不登录）：

1. 跟新域 chunk 抄 `fileKey`  
2. 打旧 host `/json/view/file/downloadFile?fileKey=`（或同类）  
3. 对照：乱填 fileKey 应空/错，真 key 出图  

算成：私有桶执照/证件原图真下到。

假点：把 301 新域名当整站废；mock fileKey 当下占位且乱填也出同一张图。单站没中不删短表这行。密钥实值、完整 JS 不进本篇。

### 分享鉴权 false 仍下媒体（短表有指针）

认：云录制分享；鉴权接口有 `download_enable`/`view_minutes_enable`。或会议 JSON 网关根本没有 `permission/auth`（404 别停）。

打（不登录）：

1. `download-multi-record-file` **和** `sign-multi-record-file` 都打（要 `auth_share_id`+`resource_type`）。国际 JSON 网关缺 `sharing_id` 只回 `2710500 参数非法`，`auth_share_id` 和 `sharing_id` 一起带才签发 MP4；缺了会当没洞。**POST JSON 报「录制 id 不能为空」别停，改 GET query 把 record_id / auth_share_id 放进 URL。**  
2. 没有鉴权口不要当成没入口：直接打 `public/record-detail/download-multi-record-file`。  
3. 纪要/时间线 `get-full-summary` / `query-timeline` 只填 `record_id` 也试，不要默认必须带 share。  
4. COS 无 Referer 的 403 **不是终点**：带分享页 Referer 再 GET。  
5. `permission/get-cfg` 看会不会吐同会其它 record。  
6. 只拿到 url 没 GET 到 MP4 算半条，继续跟。  

算成：鉴权写 false 仍拉到真 MP4（ftypisom+体积）；或只要 record_id 出纪要全文（不是标题）。

假点：鉴权真拦了、下不到文件；只有公开说明书；纪要只要标题没有正文。单站没中不删短表这行。

### 密码分享回包带明文提取码（短表有指针）

认：分享详情 JSON 一边 `need_pwd` / `auth_level`（或同类）表示要提取码，一边 auth 对象把明文提取码放进 `pass_word`（或同类）。或落地 HTML / `syncData` 内联同一明文码。

打（不登录）：

1. 先空着提取码打查看口。对照：文件列表应空，闸字段应是要码。  
2. 同一份回包里抄明文码，填回查看口。对照：空密时列表空、填了才出 `file_id`。  
3. **落地 HTML / `syncData` 里已经有明文 `pass_word` 就直接抄**，不必先打 View CGI。  
4. 拿 `file_id` 和这份码打下载口，跟到真文件头（PDF/ZIP 一类正文），不要停在 JSON 有码。

算成：拿到提取码并下到密码分享正文，不是空密直接出文件列表。

假点：`pass_word` 是哈希抄了登不进；空密 View 已经出文件（那是无提取码分享，不是这枪）。单站没中不删短表这行。
密钥实值、完整 JS 不进本篇。
