# SRC 漏洞收取标准

本文件是平台的漏洞产出质量纪律：**宁可少报，也不要数量**。只产出 SRC 平台可直接收取、有真实危害、可复现的漏洞。标准正文按次读取，注入到工具集含 `report_finding` 的角色（worker/planner/pentest/auto）的提示词（代码固定段）；文末「类型目录」（§十三 机器可查目录）是规划选型、标准卡、类型归属与上限的唯一机器来源（热改后下次读取即生效，无需重编译或重启）。retester 走自己的提示词纪律（复测三态结论）。

## 一、总原则

1. **宁缺毋滥**：只报告有真实危害、SRC 平台大概率收取的漏洞。无把握时报 inferred 事实（record_fact），不报 finding。
2. **证据底线**：每条 finding 必须有「完整利用步骤 + 实际响应证据」。理论可利用、前置条件无法满足的，一律不报（TSRC 口径：仅理论可行如 dnslog 回连、仅可爆破、仅报错 → 拒收）。
3. **挖掘期按目录选型**：规划者从 §十三 类型目录选择 `collect: yes` 的类型建意图，执行者按本类标准卡取证；上报类型与意图锚定，省略 vulnclass 时沿用意图类型，不得改报其他类型。`collect: no` 不建漏洞验证意图、不收 finding，只记录 fact 或转向可收类型；名称/摘要中的词语不参与类型判定。证据与定级仍按 §四、§十、§十一 执行。

## 二、公开性检查（每条 finding 上报前必过）

**公开性检查 = 回答一个问题：这到底是不是"符合业务预期的产品设计"？**（TSRC【无】级原文口径）

以未登录/无凭据会话按以下两条判定，任一命中即视为设计如此，作废记 fact，不上报：

1. **内容公开性**：报出的数据本来就无鉴权公开可达，且不构成「叠加攻击面」。用户名、邮箱、程序名、公开 UUID、robots.txt、版本号 banner、内网 IP 字符串、phpinfo 类报错——均为公开信息（HackerOne 口径 public by design），单独出现不构成漏洞。
2. **意图公开性**：该行为出现在官方文档/产品公告/正常业务流程中，或入口本就面向公众开放（公开主页、分享页、排行榜、公开 API）。判定看**危害是否为 0**，不是"看起来奇怪"。

**密钥例外（反向规则）**：泄露物若是真实密钥/凭据且资产可公开访问，公开性检查**不豁免**——公开性只豁免无危害信息，不豁免可利用凭据（Bugcrowd VRT：Known Public Information 落 P5，而真实密钥+公开资产可到 P1）。

完成判据：找到未登录可见的正常前端入口拿到同样数据 → 作废；找不到入口、且同域基线接口确实拒绝匿名 → 通过。

## 三、明确不收类型（默认禁止挖掘/上报）

> 以下 13 条是「明确不收类型」的人类可读口径；机器侧只读 §十三 目录中 `collect: no` 的条目。规划期拒建 `collect: no` 类型的漏洞验证意图；执行期按所选类型的标准卡证明；上报期与意图类型锚定，`collect: no` 拒收并引导 record_fact。出现升级证据时，由规划者按实际危害选择目录内可收类型另建意图，worker 不临时改报类型。正文表格与目录需保持一致。

| # | 类型 | 升级条件（满足才可报） |
|---|---|---|
| 1 | Self-XSS、无敏感操作的反射 XSS | 反射点位于鉴权/支付/个人资料等敏感页面上下文 |
| 2 | 低危 CSRF（改资料类） | CSRF 可触达敏感操作（改绑手机/邮箱、资金操作、管理操作） |
| 3 | JSONP 劫持、CRLF 无利用面 | 能实际带出敏感数据 / 完成可演示的危害 |
| 4 | 信息泄露（报错/目录列表/.git/备份）无进一步利用 | 从泄露内容实际还原出可利用物（如源码→拿到注入点/凭据） |
| 5 | 弱口令/默认口令 | 登录的是高权账户或可横向影响 |
| 6 | 理论 IDOR 无数据证明 | 以受控 A/B 账号展示跨身份读取非公开真实业务数据或完成无权操作 |
| 7 | 未授权接口但返回无敏感数据 | 返回字段含手机号/订单/身份等业务敏感数据，**且该接口非公开页面数据源（过公开性检查）** |
| 8 | 端口/指纹/版本披露 | 无（一票否决） |
| 9 | 点击劫持、iframe 嵌套 | 无（一票否决） |
| 10 | 无回显/无利用链 SSRF | 拿到内网实际响应内容并可进一步操作 |
| 11 | 用户名/账号/手机号枚举、存在性与注册状态泄露（响应差异 oracle） | 从枚举实际走到接管（撞库成功登录他人账号）或批量泄露的用户清单本身即敏感数据 |
| 12 | 短信轰炸/无频控发码（骚扰类） | 从发码链实际走到任意账户接管或真实资损；仅无频控、匿名可发、可跨号下发均不收 |
| 13 | 仅凭状态码/报错/响应差异判定的"漏洞"（403→200、500 报错、响应不同） | 从差异实际还原出数据或完成操作（盲注需时间差+数据内容）；差异本身永远不是危害 |

## 四、可收取类型的最低证据线（危害最小证明物）

每个类型定义「危害最小证明物」——拿不出证明物 = 不成立，报了也会被平台驳回（漏洞盒子口径：SQL 注入必须注出一条数据，单纯报错无危害证明将被忽略）：

| 类型 | 危害最小证明物（硬条件） |
|---|---|
| 注入类（按实际结果） | SQL/ORM 注出一条真实数据，库名仅作适用的 SQL 查询最小样本；NoSQL/XPath 取实际查询数据，SSTI/表达式取越过模板或表达式边界的服务端数据/执行实证，XXE 取越过实体解析边界的文件内容/内网响应。非 SQL 结果不要求数据库名；单纯算术回显、报错、时差或回调只记 fact |
| 越权/IDOR | **受控 A/B 交叉证明**：B 无权访问 A 的非公开资源，却读到与 owner 视图一致的内容或完成由 owner 独立确认的修改；有拒绝基线且公开性检查通过。合法访问自己的数据不成立 |
| 敏感数据泄露 | 跨越身份/权限边界获取非公开真实业务数据，≥3 个与已证危害相关的敏感字段，公开性检查通过；可用受控 A/B 账号和资源证明，只收集最小充分样本，不把公开/样例数据当危害 |
| SSRF | 服务端发出 + **回显内网数据**（云元数据/内网 banner/内网页面）；仅 DNSlog = 理论可行不收（回显分级按各家 SRC 表） |
| 认证绕过/接管 | 受控 A/B 双账号证明 B 在缺少 A 正当凭据/授权时获得 A 的身份或权限，并核实会话主体与实际操作；说明前置条件，不把单个样本外推为任意用户 |
| RCE/命令执行 | 真实命令执行实证（能执行命令本身就是危害） |
| 业务逻辑/资金 | 受控账号/测试资源中操作真实生效，突破金额、余额、订单或状态机等业务不变量；保存正常对照和前后状态。按预期修改自己资源不成立，无需第三方损失 |
| 文件上传 | webshell 可执行或存储型 XSS 真实触发；纯存储不解析不成立 |
| 任意文件读取 | 越过路径/权限边界读取非公开服务端文件，核对路径、内容与正常拒绝基线；可用隔离的私有受控标记文件证明，不为取证读取无关秘密 |
| 任意文件写入 | 越过预期目录或权限边界写入/覆盖文件，以独立读取或实际加载证明落盘及影响；使用隔离位置和可清理标记，普通上传存储不成立 |
| 不成报 | 用户名/账号/手机号枚举、短信轰炸、仅状态码/报错差异、CORS、安全头缺失、Cookie 标志位、单纯密钥/token 泄露（只作链证据） |

**受控证明边界**：受控 A/B 账号和测试资源可分别代表不同身份、角色或资源归属；真实身份/权限或业务不变量突破才成立，合法访问自己的数据不成立。证明无需第三方损失或无关数据收集；最小样本只证明已观察能力，未验证的规模不得用于抬高等级。

**机制与结果分离**：技术利用路线的机制家族描述如何触发，规范类型名描述本意图要验证的漏洞结果，两者不互相代替。已保存意图的显式 proof 保留；新观察支持另一结果时先 record_fact，由 planner 按目录另建类型化验证意图。worker 不得改标签、改指其他 intent_id 或覆盖原 proof 绕过归属。

## 六、硬门（所有漏洞必过，缺一不报）

1. **先证伪**：假设"这是正常功能"，主动跑否定实验。三类：① 不存在的值跑同协议排除 catch-all；② 合法 body 重测排除假阳性；③ **公开性检查**（§二）排除设计如此。任何一类证伪掉 = 作废不报。
2. **PoC 可复现**：原始请求或验证命令可重放，附必要的输入、前置条件和实际输出；非 HTTP 或未抓包时用命令/日志等可核验证据，不要求流量绑定。
3. **危害是链路终局**：数据泄露/接管/资金/RCE/横向的终局结果，不是中间信号（枚举出用户名、拿到 token、摸清拓扑、状态码/报错差异都不是终点）。
4. **服务端/权限边界确认**：不是浏览器 JS 假象/调试功能/渲染。

## 七、查重（上报前必查）

同一资产 + 同一根因 + 同一接口 + 同一影响面 = 同一漏洞：**补强已有 finding，不新写**（漏洞盒子同一漏洞源合并条款）。先查探索图与已有 findings 再上报。

## 八、不挖清单（挖掘阶段直接跳过，不是报不报的问题）

以下方向**一开始就不要投入探索**——它们要么不在 SRC 收取范围，要么中间信号成报率极低。发现候选点时只允许花 1-2 次请求确认能否升级到链路终局，不能升级立刻放弃并记 fact 转向，不许深挖（这些方向同步登记为 §十三 目录的 `collect: no` 条目，规划期据此拒建、上报期据此拒收）：

1. **用户名/账号/手机号枚举、注册状态/存在性 oracle**：响应差异本身不收。只有当能从这个枚举继续走到撞库接管、任意密码重置、或枚举产物本身即敏感数据清单时才值得投入，且投入点在「下一步利用」，不是「再验证几遍差异」。
2. **短信轰炸/无频控发码**：骚扰类危害，各 SRC 基本不收。发码接口只在两种情况继续：验证码可预测/可绕过（→ 认证接管链）、或发码进入其他高危链（如配合越权改绑）。纯「无频控、可跨号、无图形码」到此为止。
3. **仅凭状态码/报错/响应差异判定的"漏洞"**：403 变 200、500 报错、响应长度不同、返回结构不同——**都不是漏洞**，只是信号。任何基于差异的候选必须先回答「差异背后的危害是什么」，用数据或操作证明，不能只拿差异本身当结论。
4. **纯扫描器/指纹/端口/版本类产出**：扫描出的端口、指纹、版本 banner 记 fact 供后续利用，永不成报。
5. **批量注册/垃圾提交/留言污染类**：匿名表单可无限提交是设计如此（公开业务流程），不构成危害。

## 九、挖掘方向

探索力气按「**可收性 × 危害 × 证据**」分配：真实入口上的具体中间证据、可控危险输入或明确组件利用链优先，只有技术栈猜测的路线低优先。类型目录限定可收类型与证明物，type_coverage 检查触顶，不是必测配额，也不按目录顺序覆盖。声明 vuln_type 与 proof（缺省取目录证明物）；纯侦察可省略类型。执行者按本类标准卡 proof/signals/stop 取证止损，拿不到证明物记 fact；上报与意图类型锚定，按证据如实定级。

1. **注入类**：SQL/NoSQL/ORM 注入、模板注入（SSTI）、表达式注入（SpEL/OGNL/EL）、XPath/XXE。触发启发式：参数值回显或报错差异、响应时间可操控、返回内容随输入结构变化、模板/表达式/序列化语法被解析。
2. **命令执行与反序列化**：RCE/命令执行/代码执行、反序列化利用链（Fastjson/Jackson/pickle/phar/ViewState）、定时任务与工作流节点。触发启发式：系统命令拼接、eval 类入口、出现序列化数据特征即优先验证。
3. **SSRF**：所有接受 URL/域名/IP 的参数（webhook、图片/文件抓取、导入、代理、回调地址），探测内网 + 协议（file/gopher/dict）。触发启发式：URL 参数触发服务端外连，拿到内网实际响应才算。
4. **认证绕过与账户接管**：JWT/session 伪造、密码重置/验证码逻辑缺陷、OAuth 回调缺陷。触发启发式：受控 A/B 双账号验证身份/权限突破，说明前置条件与已验证范围。
5. **存储型 XSS**：内容持久化后在他人生效上下文触发（个人资料/评论/工单），能打到他人 cookie 或管理员；反射型按明确不收类型 #1 处理（敏感页面上下文可升级）。触发启发式：输入入库后出现在他人可见页面且未编码。
6. **文件上传 getshell**：解析漏洞、双后缀、竞态、.htaccess。触发启发式：webshell 可执行才算，纯存储不解析不成立。
7. **业务逻辑**：支付金额/数量篡改、负数与并发竞态（余额/积分/优惠券）、订单与状态机篡改、越权操作。触发启发式：受控账号/资源上的操作真实生效且突破业务不变量，正常业务操作不算。
8. **文件读写与敏感数据结果**：从路径、模板、解析或查询等机制发现的结果，按目录中适用的任意文件读取、任意文件写入或敏感数据泄露意图验证；普通存储、公开非敏感响应与组件指纹不升级。

**访问差异与真实危害**：不主动规划仅证明普通访问差异的验证意图；普通越权/未授权线索主要作为技术链入口。批量敏感数据、核心账户接管等真实高危害仍可验证上报，保留 A/B 交叉证明、公开性检查与既有证据/定级标准，同类触顶后停止新增投入。

**同类上限（默认 3，§十三 机器可查目录维护）**：单任务同一规范类型的有效产出（pending + confirmed）触顶后，停止新增该类型探索或续跑，转向其他有依据的方向；已隔离/误报/重复/忽略不占计数。已经取得、符合收取纪律的独立根因证据仍可登记：先对照已有 finding，在 description 说明不同成因，并用 evidence 或已核实流量支撑。新 URL、名称、严重度或类型标签不是独立依据；同根因补强已有 finding。接收已有证据不重开已停止路线。

**别名折叠（vulnclass 写法归一）**：任意写法先做机械归一（大小写/空白/连字符），再查 §十三 目录折叠到规范名；规划期仅接受目录中 collect: yes 的类型，目录外类型先补目录再建漏洞验证意图。上报期没有类型化意图锚定时，目录外新写法仍自成一桶、照常计数并允许上报；有锚定时须与意图类型一致。

## 十、定级纪律

- **定级锚 SRC 平台体系**（严重/高/中/低 + 各家专属规则），不写 CVSS 分数；无 exploit 的评分封顶【中】（TSRC 口径）。
- **critical**：RCE、SQL 注入拖库、直接获取大量真实用户数据、核心账户接管。
- **high**：存储 XSS、成熟利用链的越权批量数据访问、支付逻辑漏洞。
- **medium**：单用户越权、反射 XSS（升级后）、需多条件串联的泄露。
- **low**：仅在前三类都不适用、但确实有真实危害时使用。
- 拿不准级别 → 降级不升级；实在拿不准 → 记 fact 交人工判断，不硬报。

## 十一、复测纪律

- 复测结论 reproduced 才算本次复现佐证；inconclusive 表示会话、环境、工具或证据不足，保留原发现状态并记录具体原因。连续无法复现的次数不构成误报证据；只有成功完成且结论为 fixed 的复测才自动标记已修复，人工处置仍由人工决定。
- 已绑定的流量证据快照含完整利用响应（证明角色）时，可作为已有利用证据；历史证据不替代独立复测中的本次实际验证。
- AI 生成的报告必须依据实际验证证据（请求/响应原文、命令输出或日志），不能用推测补齐危害。流量绑定可选，未采集和非 HTTP 场景保留已有可核验证据；不为补包重复探测，不在交付报告中写缺失流量等过程说明。

## 十二、技术利用路线的续探与止损

- **路线身份**：按任务 + 入口 + 机制族 + 相关组件/参数确定。改变摘要、payload、机制拼写或意图 ID 不重置去重与预算；同一入口下应填入有区分度的组件/参数。
- **状态完整**：路线应保留入口、机制族、组件/参数、假设、前置条件、已测变体、结果与剩余假设，并可从既有意图和事实恢复。
- **有界续探**：同入口同机制族默认最多创建 6 次执行意图（续跑也计数），运行配置可调整；上限不是目标。危害已证实（impact）、路线级有效阴性（negative）、前置条件可靠证伪（prerequisite_disproved）或关键变体耗尽（variants_exhausted）时立即停止。
- **信息增量**：同路线后续意图通过 parent_ids 引用此前未用于该路线、含实际动作和可定位观察的新 fact/finding，说明缩小的解释或变化的前提。tested 仅保存已执行历史；未执行计划、重复证据、nonce、新 ID 与改写的摘要/结果不算增量。
- **无信息换向**：连续 3 个规划轮次同路线没有可核验的新观察时换方向。真实新观察才重置计数；结论性停止须有 observed 观察及相应执行、证据支持，不把旧结论或任意引用升级为停止权威。
- **优先级**：全局任务预算、worker 超时、任务取消、人工停止与既有类型上限优先于路线续探。触顶、有效阴性或预算耗尽时，不得以“类型尚未覆盖”等理由提权重派；调整优先级须记录理由。
- **状态区分**：progress（路线进展）、negative（有效阴性）、blocked（技术受阻）、no_interaction（健康窗口暂无交互）、service_unavailable（OOB 服务不可用）、observation_incomplete（观察窗口未完成）、insufficient_impact（有交互但危害不足）与 impact/prerequisite_disproved/variants_exhausted 必须保持不同状态，不得统一折叠为失败。
- **OOB 解释**：暂无交互或 OOB 服务故障不证明目标无漏洞，不计作路线新信息，也不自动触发整个 worker 重试；回调只是中间证据，仍需继续取证到实际危害。

## 十三、机器可查目录（类型归属与上限的唯一机器来源）

本块是 Go 侧（规划选型、标准卡、上报类型归属校验、同类上限、类型覆盖态势与别名折叠）读取的**唯一机器来源**。热改后下一次读取即生效，无需重编译或重启；已存意图的显式 proof 保留。正文的 §三 明确不收类型、§八 不挖清单、§九 挖掘方向只做人类可读说明，若与目录冲突以目录为准。

行格式：

- `cap: <数字>`：全局同类上限（缺省 3）。
- `type: <规范名>`：开启一条类型；`collect: yes` 可收（新增探索受同类上限约束），`collect: no` 明确不收（规划拒建、上报拒收）。
- `aliases: <别名…>`：空格分隔的单 token 别名（折叠时抹掉空白/大小写/连字符，所以每个别名内部不要带空格）。
- `proof:` 危害最小证明物（与 §四 证据线同源）；`signals:` 触发启发式；`stop:` 止损线（`collect: no` 条目的拒收文案来源）。
