# 提交稿是交付物：写入侧骨架校验，导出不带过程腔

`findings.report` 是 reporter 逐漏洞撰写的 SRC 提交稿，会被直接提交给审核方，但此前它没有任何交付纪律：入库零校验，指令源互相矛盾（update_finding_report 工具描述建议旧五节、系统提示词要求十节），导出层还注入「证据版本/绑定数量/报告待更新」等过程元数据。2026-11-20 一次运行中连出四份旧五节结构报告，全部原样落库——提示词约束已被证明挡不住指令矛盾。决定：

- 提交稿在写入侧按报告骨架硬校验：缺必需节（漏洞名称、漏洞复现步骤（POC）、漏洞危害、修复建议）或超 300 行拒绝入库，agent 收到错误后自行重写。
- 导出（FindingsMarkdown / SingleFindingMarkdown）不输出证据版本、绑定数量、报告待更新等过程元数据；绑定角色一律用中文名。
- 指令源统一：工具描述与触发消息与系统提示词同一骨架，不再给第二套结构建议。

**Consequences**：校验放在写入侧而非渲染侧——渲染侧拦不住已落库的垃圾；代价是偶尔被误拒的报告要多一轮重写。已落库的旧五节报告不受影响，需重触发 reporter 重写。
