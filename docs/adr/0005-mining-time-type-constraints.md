# 判定位置前移：挖掘期结构约束取代上报期词表闸

上报期按漏洞名称、摘要中的词语判断收取范围，会把已证实危害与中间信号混为一谈；发现已经产生后再隔离，也无法挽回挖掘阶段浪费的预算。我们决定把类型选择前移到规划期：SRC 收取标准末尾的类型目录是唯一机器来源，规划者只从可收类型建漏洞验证意图，执行者领取本类标准卡，按危害最小证明物、触发启发式与止损线执行。纯侦察可以不带类型。

上报类型锚定意图：省略类型时沿用意图类型，别名折叠后一致才接收；明确不收类型拒收并引导记录事实。有升级证据时由规划者另建符合实际危害的可收类型意图，执行者不通过换名绕过归属。没有类型化意图锚定的目录外历史/新类型上报仍允许，历史 finding 不回填、不重判，既有隔离数据的语义保留。类型覆盖态势只给规划者，用于选择未触顶方向；证据线、定级纪律与同类上限不因类型偏好改变。

本决策延续 [ADR-0004](0004-type-diversity-soft-loop.md) 的反馈回路与类型数据不进运行逻辑常量原则，将其类型来源统一到机器可查目录。标准正文与内嵌默认同步维护，文件热改在下一次读取生效，已存意图的显式证明物保留。默认提示词变更通过各角色的新 reseed flag 一次性追加版本，已有版本留在历史中，升级后的自定义不被重复覆盖。

## Considered Options

- 上报期词表闸：拒绝，名称/摘要不能证明危害，别名与改名容易改变判定，且拦截位置太晚。
- 事后再加复核角色：拒绝，新增轮次与延迟仍在错误方向投入之后，不能替代动手前的证明目标；既有复测职责保持。
- 强制抓包或绑定流量：拒绝，未开启采集和非 HTTP 漏洞也可有可验证证据；流量绑定保持可选，类型约束不依赖抓包开关。
- 按类型目标硬判完成或改变严重度：拒绝，不可达类型可能卡死目标，挖掘偏好不能替代真实危害与证据线。
