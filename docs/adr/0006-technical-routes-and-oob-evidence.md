# 高价值挖掘按技术利用路线推进，带外交互作为中间证据

高价值漏洞挖掘以反序列化、组件已知漏洞、模板/表达式注入、SQL 注入、SSRF、任意文件读写及其升级链为主攻方向；未授权、越权主要作为入口或组合条件，不主动规划仅证明普通访问差异的验证意图。批量敏感数据泄露、核心账户接管等已证实的高危害结果仍按既有收取纪律处理，不以漏洞偏好扭曲定级或入库门槛。

技术利用路线描述入口、技术机制、前置条件与验证路径，漏洞结果仍归属既有类型目录；不能用某类型已有 finding 或意图代替具体路线的验证状态。默认启用可切换至自建服务的 Interactsh 带外验证能力，未配置自建地址时采用官方公共默认服务；唯一探测标识及其回调是带外证据，证明发生过交互，不单独证明 RCE、数据泄露或完整漏洞链。涉及公共服务的隐私、可用性与授权目标约束须明确呈现。

## Considered Options

- 把反序列化、组件 CVE、SSTI 分别当作最终漏洞类型统计覆盖：拒绝，会把技术机制与 RCE、数据泄露等漏洞结果混淆，掩盖同一类型内未测试的利用路线。
- 只以未授权、越权数量衡量高危挖掘：拒绝，这类入口容易重复，不能代表用户所需的高价值技术漏洞检出能力。
- 仅凭一次 DNS/HTTP 回调直接上报漏洞：拒绝，回调只能归属到具体探测，仍需结合实际响应、命令输出、内部内容或其他危害证据。
- 要求自建 OOB 服务才启用：本次不采用，用户明确选择默认可用的公共 Interactsh 服务，同时保留自建服务配置。
