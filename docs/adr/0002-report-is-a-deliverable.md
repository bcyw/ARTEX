# 报告是交付物：只收已确认漏洞，不写过程与任务元信息

报告会被直接提交给审核方，也会被整段复制给其他 agent 复现，所以它必须是一份干净的交付物，而不是工作记录。决定如下：

- 只收 `findings.status='confirmed'` 的漏洞，不再按 `exploration_nodes` 的 `kind='finding'` 全量渲染。
- 不出现任务目标、任务 ID、生成时间、测试资产范围这类任务元信息（现有 `report.Markdown` 的摘要段整体移除）。
- 不出现"我使用了某工具""未绑定流量""待补充"这类过程说明或占位语；缺什么就少什么。
- 不输出截图段（系统没有截图能力）。
- 章节骨架固定为 vuln-report-skill 的十节结构：漏洞名称、漏洞等级、漏洞类型、漏洞影响资产、漏洞URL、漏洞描述、〔测试账号与会话上下文〕、漏洞复现步骤、漏洞危害、修复建议。
- 产物是 Markdown；DOCX 成稿交给 `/report` skill，不在服务端复刻版式。

**Consequences**：老数据的 `summary` 是 agent 自由文本，可能自带过程腔，渲染层无法清洗，只能靠提示词约束后续上报；未绑定流量的发现只剩原始 PoC 文本，读者无法从报告判断是缺数据还是开关未开。
